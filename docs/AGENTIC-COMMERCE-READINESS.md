# Machine-readable commerce readiness

Sprint 6 · Foundations only. **No autonomous purchasing, no external feed submission, no platform approval claimed.**

## 1. Public catalogue: `/catalogue.json`

Generated by `scripts/generate-catalogue-json.mjs` from `src/data/catalogue/` — the same source as the site pages, the server's private `api/data/catalogue.json` and the structured data. `npm test` fails if it drifts. It carries the same `catalogue_hash` as the server copy.

For each public product: id, name, description, positioning, product type, commercial model, canonical URL, image URL (product photographs only), availability (`ORDERABLE_ONLINE`, `QUOTE_ONLY_BY_ENQUIRY`), enquiry URL, timing, included revisions, disclosures, whether a song experience must be in the same order, and variants with SKU, price (decimal string, minor units, GBP), online orderability, fulfilment, shipping requirement, song capacity, format (digital / picture disc / standard vinyl, size, shape, records, gatefold), personalisation requirements, add-on eligibility, features and a `/create?sku=` URL for song experiences.

It contains no supplier, cost, margin, routing, internal id, customer or configuration data. Inactive or unsold products (gift vouchers, the Cruise Ship DJ Bible) are absent. It has not been submitted to Google Merchant Center, OpenAI or any marketplace; doing so needs accounts, shipping settings and policy review (see §6).

## 2. Personalisation a machine client must understand

| SKU | Unit | Count | Each unit needs |
|---|---|---|---|
| `moment` | memory | 1 | story ≤ 300 chars; optional "about" ≤ 120; style (catalogued, own words, or MCB's choice); optional photo |
| `keepsake-7-picture-disc` | memory | 1 | as above |
| `keepsake-10-heart-picture-disc` | memory | 1 | as above |
| `keepsake-10-picture-disc` | memory | 3 | as above |
| `keepsake-12-picture-disc` | memory | 4 | as above |
| `journey-6` | chapter | 6 | as above |
| `journey-12` | chapter | 12 | as above |
| `personalised-music-plaque` | plaque | 1 | photo (required), song title ≤ 120, artist ≤ 120 |
| `lyrics-frame-*` | frame | 1 | a song from the same order; heading ≤ 80 |
| `priority-replacement` | — | ≤ eligible Keepsakes | an eligible Keepsake in the same order |

Describing these requirements grants nothing. The server still validates every field, requires the customer's consent to the current terms, quotes delivery for the destination (refusing unavailable destinations), prices from its own catalogue, and takes payment only through Stripe Checkout completed by the customer. Approval of the finished music is a separate customer action via a private link.

## 3. Action map (existing endpoints, not a public developer API)

| Intent | Endpoint | Caller today | Notes for a future versioned API |
|---|---|---|---|
| Quote an order | `POST /api/order-quote` | website | stateless, rate-limited; candidate for `v1/quotes` |
| Create order + personalisation | `POST /api/order` | website | needs `Idempotency-Key`; consents mandatory; returns checkout token |
| Add photo | `POST /api/order-upload` | website | checkout token; private storage |
| Retrieve saved order | `POST /api/order-status` | website | checkout token |
| Create checkout | `POST /api/checkout/session` | website | returns a Stripe-hosted URL; the customer pays there |
| Order progress | `POST /api/order-progress` | customer link | secret link token only |
| ~~Approve / request changes~~ | `POST /api/order-approval` | — | **Retired** (Single Creative Authority, 15 Sept 2026): records nothing |
| MCB LIVE enquiry | `POST /api/live/enquiry` | website | no quote, availability or deposit |
| Bespoke enquiry | `POST /api/concierge/enquiry` | website | no price |

Staff and admin actions (`/api/crm/*`) are never public and require the CRM key.

A future machine-client API would need: explicit versioning (`/api/v1/`), client authentication and per-client rate limits, a machine-readable error schema (the current `error`/`message`/`fields` shape is stable and could be adopted), published idempotency rules, and a signed-consent flow. None of that is built; the same-origin checks on today's endpoints deliberately keep them website-only.

## 4. Automation events (`GET /api/crm/automation-events`)

Internal, CRM-key only, read-only (POST → 405), no side effects, ordered by id with two cursors (`after_order_event`, `after_enquiry_event`) so polling is stable. Payload: event id, name, MCB or enquiry reference, timestamp and non-personal detail (round numbers, channels, staff name). No customer names, emails, stories, addresses or amounts.

| Event | Meaning |
|---|---|
| `ORDER.PAID` | Stripe confirmed payment; MCB reference issued |
| ~~`CREATIVE.READY`~~ (retired) | Music finished internally, not yet with the customer |
| `ORDER.READY_FOR_PROCESSING` | Verified payment: the new order is ready for MCB's creative team |
| `QUALITY_CHECK.READY` / `.PASSED` / `.FAILED` | MCB's internal quality check (never customer-facing) |
| `REVEALED` | A digital creation was revealed to the customer |
| `FULFILMENT.READY` | Physical order may be placed with a supplier **by a person** |
| `DISPATCHED` | Staff recorded dispatch |
| `DELIVERED` | Staff recorded delivery |
| `FOLLOW_UP.DUE` | A follow-up with the customer is due |
| `MCB_LIVE.ENQUIRY_RECEIVED` | New MCB LIVE enquiry |
| `BESPOKE.ENQUIRY_RECEIVED` | New Bespoke enquiry |

No event carries financial or supplier authority, and nothing is connected to an external agent or tool.

## 5. What is deliberately not built

Autonomous ordering or payment; a chatbot; `llms.txt` or other speculative files; external feed submissions; marketplace integrations; any credentialed third-party connection.

## 6. Before any feed submission (post-launch)

Verified shipping rates and regions, returns policy mapping, tax/VAT statement, GTIN exemption (custom goods), product photography that shows each product itself, and the platform's own review.
